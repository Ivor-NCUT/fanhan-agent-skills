# 课程文稿精修增补规则

这份规则来自飞书课程稿《第三课：出海增长基本流程与团队搭建》的正文、版本信息和评论复盘。它用于补强 `source.md` 中偏“从零设计课程”的流程，让 skill 在已有文稿和评论改稿场景里更稳定。

## 先判断本课的真实教学任务

不要急着抽一句“核心观点”。系统课每一课可能承担不同功能：

- 建立全景图：让学员知道业务流程、阶段位置和团队配置。
- 纠正误区：指出常见错误做法和代价。
- 给方法模板：让学员照着做一张表、一次访谈、一次调研。
- 训练判断标准：让学员知道何时该继续、停止、放量或升级团队。
- 衔接前后课：回收上一课概念，引出下一课动作。

如果正文里写的“核心观点”与课程真实任务不一致，先调整课程任务。比如“正确流程比砸钱更重要”是判断，但“让读者建立不同阶段增长策略与团队配置的全景图”才是这一课的教学任务。

## 评论处理流程

处理飞书评论时按四类判断：

1. 已吸收：正文已经体现评论建议，交付时标记即可。
2. 待处理：评论指出的问题仍存在，要改正文。
3. 当前正文不一致：评论引用的是旧稿内容，先比对当前正文，再决定是否忽略或转成规则。
4. 需 CEO 判断：涉及品牌口径、价格、承诺、客户关系、公开发布风险、事实来源不确定时，不直接替 CEO 定。

不要只看评论是否已解决。已解决评论也可能沉淀了稳定规则；未解决评论也可能因为正文后续改动而失效。

## 结构修订原则

- 开头要同时完成三件事：承接上一课、说明本课任务、抛出贯穿主线。
- 强句不要只放结尾。能成为主线的句子要在开头出现，中段用案例解释，结尾回收。
- 每个章节之间要补过桥句。尤其是“怎么挑竞品”到“怎么拆官网”这类跳转，要说明上一动作的产物如何进入下一动作。
- 避免同一失败案例重复出现。若开头已经完整展开，中段换另一类失败；若中段要完整展开，开头只埋钩子。
- 空行和短句服务于口播节奏，不是越碎越好。连续解释同一个动作时，适当合并句子，避免语义断裂。

## 段落节奏规则

课程稿要像一位老师连续讲课，不要像散文诗或短视频字幕。上一版第六课出现过“每个短句单独成段”的问题，导致读者读起来断裂，尤其是在解释名单筛选、近期活跃、渠道差异等连续概念时，频繁句号和换行会打断理解。

改稿时按下面规则处理：

- 一个段落只承载一个教学动作，比如解释概念、给判断、展开例子、补边界或布置动作。
- 一个段落通常写成一个完整句群，句群里有 2-5 个短句，用逗号、分号、冒号连接，而不是每个短句都用句号切开。
- 一个段落在飞书阅读界面里大致控制在 2-3 行；超过 4-5 行时，按语义拆段，不按句子机械拆段。
- 只有这些内容适合单独成段：章节转场、强判断、课堂提问、例句、引用模板、作业要求、需要停顿的金句回收。
- 连续列举如果少于 5 项，优先写进自然段；如果是模板字段、检查清单、作业清单，才使用列表。
- 写完后必须检查是否出现“他发过帖。/ 他评论过。/ 他在 GitHub 提过 issue。”这类字幕式断行；如果出现，合并成“比如发过帖、评论过、在 GitHub 提过 issue……”。

## 内容补强原则

- 抽象判断要配可检查指标。比如“商业化做得好”要落到定价页、套餐、客户案例、持续投放、公开评价等指标。
- 方法要给模板字段。比如竞品社媒调研表至少包含：日期、渠道、内容标题、内容形式、互动数据、CTA、目标用户、可复用动作。
- 建议要补边界。比如“两个实习生启动增长”要说明：创始人或负责人定义问题、检查产出、亲自和用户对话；实习生负责搜集、整理和执行。
- 专业分类要解释归属标准。比如大 G、Pro、SMB 不只给转化率阈值，还要解释客单价、销售周期、决策方式和样本口径。
- 可借鉴的东西要说清层级。竞品官网可以借鉴信息顺序和转化逻辑，不能照抄视觉和文案。

## 课程上线稿自检

交付课程改稿前检查：

- 本课任务是否清楚，不只是一句泛泛的核心观点？
- 是否保留主讲人署名和前后课衔接？
- 评论中的关键担忧是否被处理或说明？
- 每个方法是否有步骤、字段、标准或小公式？
- 高风险判断是否留给 CEO，而不是替 CEO 承诺？
- 语言是否像口播课程：自然、具体、能听懂，没有书面腔和禁用句式？
- 段落是否像课程稿而不是散文诗：有没有过多句号、过多单句段、过多字幕式断行？
- 是否说明哪些评论已吸收、哪些仍待处理、哪些需要 CEO 判断？
