# 搜索与证据复核

## 把要求变成线索

| 画像 | 搜索信号 | 优先证据 |
|---|---|---|
| Agent / 工程 | shipped、deployed、eval、recovery、生产、复盘 | 代码、PR、可靠性方案、失败分析 |
| AI 产品 | user feedback、retention、定价、产品迭代 | 产品、研究过程、取舍与负责范围 |
| 增长 / 运营 | activation、distribution、SEO、获客实验 | 实验设计、渠道过程、归因与结果 |
| 设计 | interaction、design engineering、交互案例 | 作品、方案约束、设计与代码关联 |

按客户真正要解决的问题生成中英文查询，保留 requirement_ids。少量高质量查询先跑，再依据缺口扩展；不为凑数量重复购买。

GitHub 先查作品，再核对作者、维护者与具体贡献。脚本内置仓库搜索和 README / 公开账号读取；PR、文件、commit 和复杂路径由 Codex 使用 gh 定向核验。仓库 owner 不自动代表全部作品由该人完成。

X 兼用于发现和联系；职位名称、粉丝与 star 只用于线索发现。LinkedIn、个人站、专业文章、Reddit、YouTube 可提供职业与实践材料。公开账号没有自愿关联职业身份时不反推私人身份。

## 播客路线

搜索“问题主题 + 访谈 / 播客 / podcast / interview”，可加小宇宙、Apple Podcasts、官网或 RSS 来源。读取简介、嘉宾介绍、章节、可访问的文字稿或节目方外链。

记录节目和单集 URL、发布时间、嘉宾/主持人角色、发言人、段落/时间定位。没有准确说话人时标记未知；单集标题、介绍和主持人的总结不归给嘉宾。

“谈过相似话题”进入发现线索；“描述本人实践”作为本人自述；有作品或独立职业证据才加强贡献判断。节目商务邮箱、RSS 作者邮箱不当作嘉宾邮箱。

已有转写优先；没有转写时不默认付费。先列出最值得补的音频及实际时长、当前报价和必要性，在授权范围内执行。

## 身份、贡献与联系方式

- 同名账号保持分开，除非有明确公开关联。
- 每条主张关联原始证据、要求 ID、阅读范围、角色和证据类型。
- 同一成果的不同页面使用 artifact_group_id；不要按来源数推算独立项目数。
- 地点以候选人公开职业证据为依据，不用公司总部代替。
- 联系方式只保留公开工作/商务用途；公开邮箱不等于可投递或仍属本人。
- 仅在真实检查账号中看到 X 私信入口时记录 entry_visible；其余保持 unknown 或实际不可用状态。

## 最后验收

先复核约 10 人，覆盖强线索、关键未知条件和贡献不足的案例。逐人检查身份、关键能力、反证、联系渠道和话术事实。用户反馈“值得联系”才作为业务质量标签。

所有字段通过结构校验后，Codex 检查推荐理由是否真由原文支持、语气是否匹配阅读范围、公开机会信息是否获准。报告完整说明资料来源、费用、未知项及未完成研究。

名单或建联草稿不自动触发发送、候选人入库或客户分享；这些后续业务动作按各自明确授权执行。
