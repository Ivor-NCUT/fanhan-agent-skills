# 理白风格写作

## 使用方式

当任务匹配该 skill 时，先判断用户要做什么：

- 诊断：用户提供已有稿件，想知道和理白风格差在哪里。
- 润色：用户提供已有稿件，想改成理白公众号风格。
- 从素材创作：用户提供主题、素材、访谈、提纲、观点或业务现场，想写成完整公众号文章。
- 局部优化：用户只要标题、开头、结尾、小节或转化段。

如果缺少关键信息，最多问一个最影响成稿的问题。能基于现有素材先产出可审查版本时，先产出版本。

需要更完整的风格来源时，读取 `references/source-style-overview.md`。需要看样本标题和来源时，读取 `references/source-samples.md`。

## 风格核心

- 作者站位：真实前线的内容型公司主理人、知识付费操盘手、IP 教练和服务者。
- 读者关系：既是白哥式同行提醒，也是高势能主理人的筛选与召唤；对客户讲负责，对同行讲丑话，对普通读者讲真实体感。
- 核心价值：把真实业务现场、金钱结果、客户交付、流量数据和个人感受转译成可迁移的商业判断。
- 思维内核：互联网商业是服务业，也是系统战；流量、交付、口碑、团队、心力、筛选和周期感共同决定结果。
- 语言质感：口语、强判断、短段落、数字密集、情绪外露但不脱离业务逻辑。
- 结构节奏：真实现场开场，强判断压题，中段拆错误动作和底层原因，后段给方法、边界或行动召唤。
- 典型开头：突发现场、扎心判断、里程碑战报、共情提问。
- 典型收尾：硬核短句、共同成长、直接转化、情绪回落。

## 写作原则

理白风格不是表面口癖模仿。优先复刻以下顺序：

1. 真实业务现场：先有事件、数据、成本、客户、团队或个人处境。
2. 强判断：把现场压缩成一句读者能记住的话。
3. 商业解释：说明为什么多数人会做错，以及错在哪里。
4. 可迁移规则：把个人经验转成读者能执行的判断、公式、清单或动作。
5. 边界和筛选：该拒绝的流量、客户、合作和关系，要说清楚系统原因。
6. 交付伦理：再强势也要落回服务、口碑、承接和长期复利。

## 工作流

### 诊断

1. 判断稿件属于哪类内容：方法论、复盘、销售、招募、边界、年度总结或情绪现场。
2. 对照理白风格，从选题现场、强判断、结构节奏、商业逻辑、真实证据、读者关系六个维度诊断。
3. 给出 3-5 个最重要问题。
4. 每个问题给一个具体修改方向，必要时给短 before/after。

### 润色

1. 保留用户原有事实、观点、案例和边界，不编造结果。
2. 先补足真实现场：发生了什么、谁参与、数字是多少、冲突在哪里。
3. 提炼一句强判断，放到开头或第一屏附近。
4. 调整段落为短段落，关键判断单独成段。
5. 把情绪句后面接上商业解释，避免只爽不稳。
6. 输出完整改写稿，并附「主要改动说明」。

### 从素材创作

1. 识别素材里的真实业务现场和最有传播性的冲突。
2. 选择文章类型：
   - 方法论：现场 -> 判断 -> 错误动作 -> 底层原因 -> 正确做法。
   - 复盘：节点 -> 数据 -> 阶段公式 -> 关键转折 -> 可迁移经验。
   - 销售/招募：势能证明 -> 标准/丑话 -> 收益 -> 岗位或产品细节 -> 行动入口。
   - 边界：触发事件 -> 为什么必须切割 -> 系统原因 -> 新规则。
3. 先写 3-5 个标题，再写开头。
4. 正文中加入数字、客户现场、成本、团队动作或自我代价。
5. 缺事实时标注待补，不编造。
6. 输出完整文章。

### 局部优化

按用户指定部件输出 3-5 个候选，并说明每个候选适合的读者感受或传播场景。

标题优先使用这些形态：

- 强判断：`99%的自媒体IP，都是这样把用户得罪的。`
- 反常识：`卖课一年挣300万就是天花板了，但如果你换个思路呢？`
- 里程碑战报：`播放破亿，涨粉40万｜揭秘...`
- 边界宣告：`再有一次，你就滚出我的私域。`
- 真实体感：`分享赚到人生第一个1000万的真实感受（暗黑版）`

## 语言规则

### 应该写成这样

- 多用一句一段。
- 关键判断加粗或单独成段。
- 用「你看」「我说真的」「听我一句劝」「说个扎心的真相」推进。
- 多用真实数字和具体动作。
- 可以有自嘲、狠话、戏剧化类比，但后面要接逻辑。
- 用「以前/现在」「别人/我们」「表面/本质」「上坡/下坡」制造对比。

### 不要写成这样

- 不要只堆「牛逼」「哈哈哈哈」「扎心」等口癖。
- 不要编造营收、客户、截图、贵人、经历、团队规模。
- 不要只骂人，不给商业解释。
- 不要写成学院派课程讲义。
- 不要用过度精致、文艺、抽象的句子稀释现场感。
- 不要把理白写成纯粹傲慢的人。强边界背后必须有心力、口碑、交付和系统效率。

## 输出格式

除非用户另有要求，按任务类型输出：

- 诊断：先给结论，再列问题和修改方向。
- 润色：先给完整改写稿，再给主要改动说明。
- 创作：先给标题候选，再给完整正文。
- 局部优化：给候选列表，并说明适用场景。

## 边界

- 不编造作者经历、客户案例、业务数据、截图和公众号历史。
- 不洗稿；如果用户给的是竞品文章，提炼结构和方法后，用用户自己的素材重写。
- 用户事实优先，理白风格其次。
- 如果素材不足以支撑强势判断，要降低语气或标注待补事实。

## 自检清单

交付前检查：

- 是否有真实现场，而不是空泛观点。
- 是否有一句足够清楚的强判断。
- 是否把情绪转成了商业解释。
- 是否体现服务、口碑、筛选、承接、长期复利。
- 是否保留用户事实，没有编造。
- 是否避免了表面口癖化。
