# 选题调研@方比比

## Purpose

帮方比比/星辰文化在正式写脚本或拍摄前，验证一个选题在小红书和抖音上是否已经有相似爆款、别人怎么表达、用户在评论里真正关心什么，以及这个选题还能不能做出差异化。

这个 skill 不是普通搜索摘要。目标是把平台上的真实内容拆成“可用于选题决策”的材料：爆款证据、表达角度、评论需求、可复用结构、差异化机会和风险。

## Required Capability

使用 AgentReach 能力，优先读取：

- `/Users/fanhan/.agents/skills/agent-reach/SKILL.md`
- `/Users/fanhan/.agents/skills/agent-reach/references/social.md`

小红书优先用 `xhs search`、`xhs read`、`xhs comments`。注意小红书 `xsec_token` 限制：不要直接构造裸 note_id，必须从搜索结果或 feed 里的 URL/ID 继续读取。

抖音优先用 AgentReach 的 douyin MCP：

- `douyin.parse_douyin_video_info`
- `douyin.get_douyin_download_link`
- `douyin.extract_douyin_text`

如果抖音不能直接拿到字幕或正文，先下载视频或音频，再使用本机 Fun-ASR-Nano 转写。可参考 `/Users/fanhan/.agents/skills/视频文件提取文本/SKILL.md`，默认模型是 `FunAudioLLM/Fun-ASR-Nano-2512`。

## Input Handling

用户通常会给一个模糊选题，例如：

- “我想做一条讲老板为什么不要亲自管太细的视频，帮我查查有没有爆款。”
- “这个小红书选题：00 后老板招人，别人有没有做过？”
- “帮我调研一下 AI 提效培训这个方向在抖音有没有爆款。”

先把用户想法拆成 3-8 个关键词组合。关键词要覆盖：

- 直白关键词：用户原话中的行业、对象、痛点、结果。
- 平台表达关键词：小红书/抖音上更像用户会搜、博主会写的说法。
- 反向关键词：同一问题的负面表达、吐槽表达、失败表达。
- 人群关键词：老板、宝妈、职场人、创业者、学生、员工、00 后等。

如果选题完全无法判断领域、人群或平台语境，每次只问用户一个最关键问题。优先问：

> 这个选题主要想打给谁看：老板、员工、求职者、宝妈、创业者，还是某个更具体的人群？

## Research Scope

默认调研两个平台：

- 小红书：找图文笔记、视频笔记都可以，但图文笔记要重点采集封面、标题、正文和评论。
- 抖音：找视频内容，重点拿标题/文案、封面、互动数据、评论和字幕/转写。

默认每个平台先搜索 3-5 组关键词。每组关键词先看前 10-20 条结果，再筛出最相似、互动最高、角度最有参考价值的内容。

不要只看点赞数。优先纳入这些样本：

- 高互动：点赞、收藏、评论明显高于同类结果。
- 强相似：选题、人群、冲突或表达方式接近用户想法。
- 高评论价值：评论里出现真实痛点、反驳、补充案例或高频追问。
- 可迁移：虽然行业不同，但结构和钩子可以迁移到方比比内容。

如果搜索结果很少，也要明确说明“没找到强相似爆款”，并给出可能原因和改搜方向。

## Collection Fields

### 小红书样本

每条样本尽量采集：

- 平台：小红书。
- 链接或来源 ID。
- 内容类型：图文笔记 / 视频笔记 / 不确定。
- 标题。
- 封面：图片 URL 或封面描述；如果工具只返回封面链接，保留链接。
- 正文/文案：保留核心内容，避免不必要的长篇复制。
- 点赞数。
- 收藏数。
- 评论数。
- 前 10 条评论在聊什么：不要只粘评论，归纳成 3-6 个讨论主题；必要时附少量短引文。
- 博主名称。
- 博主个人简介。
- 为什么算相似或有参考价值。

### 抖音样本

每条样本尽量采集：

- 平台：抖音。
- 链接或分享链接。
- 标题。
- 封面：图片 URL 或封面描述。
- 文案/视频描述。
- 点赞数。
- 收藏数。
- 评论数。
- 前 10 条评论在聊什么：归纳讨论主题、质疑点、共鸣点、追问点。
- 博主名称。
- 博主个人简介。
- 字幕/转写文本：优先平台字幕；没有字幕时下载音频/视频后用 Fun-ASR-Nano 转写。
- 视频结构拆解：开头钩子、冲突、案例、观点、行动引导。
- 为什么算相似或有参考价值。

## Working Procedure

### 1. Clarify the Topic

把用户想法压缩成一句“待验证选题”：

```text
待验证选题：[人群] 在 [场景] 遇到 [痛点/冲突]，想获得 [结果/认知反转]。
```

如果用户没给足信息，问一个问题；否则直接进入搜索。

### 2. Build Keyword Map

输出或内部记录关键词表：

```text
核心词：
平台词：
痛点词：
反向/吐槽词：
人群词：
组合搜索词：
```

### 3. Search Xiaohongshu

用 AgentReach / xhs-cli：

```bash
xhs search "关键词"
xhs read "搜索结果中的 URL 或 ID"
xhs comments "搜索结果中的 URL 或 ID"
```

读取时控制频率，避免短时间高频请求。每次请求间隔 2-3 秒；遇到验证码、登录失效或接口错误，记录限制，不要绕过平台风控。

### 4. Search Douyin

用 AgentReach / douyin MCP：

```bash
mcporter call 'douyin.parse_douyin_video_info(share_link: "URL")'
mcporter call 'douyin.extract_douyin_text(share_link: "URL")'
mcporter call 'douyin.get_douyin_download_link(share_link: "URL")'
```

如果搜索能力不足，先用网页搜索找抖音相关结果，再把分享链接交给 douyin MCP 解析。能拿字幕就优先拿字幕；不能拿字幕再下载视频/音频并本地转写。

### 5. Transcribe Douyin When Needed

如果需要本地转写：

1. 下载视频或音频到 `/tmp/topic-research-fangbibi/`。
2. 用视频转文字 skill 的脚本或同等流程提取音频。
3. 使用 `FunAudioLLM/Fun-ASR-Nano-2512` 转写。
4. 在报告里标注“字幕来源：平台字幕 / 本地 Fun-ASR-Nano 转写 / 未能获取”。

不要把下载的视频、音频或平台素材长期保存到项目仓库；临时文件放 `/tmp/`。

### 6. Analyze, Not Just Collect

完成采集后，做四层判断：

- 有没有相似爆款：按平台分别判断“强相似爆款 / 弱相似爆款 / 没找到”。
- 爆点来自哪里：人群痛点、身份冲突、反常识、标题钩子、封面钩子、故事张力、实用价值、情绪出口。
- 评论说明什么：用户是在共鸣、求方法、质疑、补充案例、要资源，还是争论价值观。
- 方比比怎么做更好：角度改写、标题方向、封面信息、开头 3 秒、脚本结构、可避开的雷区。

## Quality Bar

交付前检查：

- 至少说明搜了哪些关键词和平台。
- 至少列出每个平台的有效样本；如果某个平台没拿到样本，要说明原因。
- 不把“高赞”直接等同于“值得做”，必须解释爆的机制。
- 评论必须归纳“用户在聊什么”，不能只说“评论很多/很真实”。
- 博主简介如果拿不到，要标注“未能获取”，不要编。
- 数据如果工具返回不完整，要标注缺失，不要估算。
- 抖音视频没有字幕时，要明确是否尝试过平台字幕、下载链接、本地 ASR。
- 涉及公开发布、客户承诺、价格、合同、品牌风险时，给出建议但升级给 CEO 判断。

## Boundaries

- 只做公开可访问内容的调研，不做绕过登录、验证码、付费墙或平台风控的行为。
- 不批量保存、搬运或复刻他人完整作品。报告里只保留决策所需摘要和少量短引文。
- 不建议直接抄袭标题、封面或脚本；只提炼结构和表达机制。
- 不对外发送、发布或评论，除非 CEO 明确授权。
