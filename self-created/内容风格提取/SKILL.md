# 内容风格提取

## 目标

把零散的历史内容变成两个可复用资产：

1. 一份飞书交付的「内容风格概述」文档。
2. 一个可安装的 Agent skill，名称为「xx 公众号风格写作」，让之后的写作、润色、诊断都能稳定复用这套风格。

本 skill 不是简单总结语气，也不是洗稿工具。它要还原作者如何选题、如何思考、如何组织材料、如何与读者建立关系，以及哪些表达习惯可以迁移到新内容里。

## 触发后先判断模式

根据用户输入选择最小可执行路径：

- **只做风格概述**：用户只给过往内容，或明确说「整理风格文档」「提取内容风格」。
- **只做写作 skill**：用户已经给了风格概述文档，并给了公众号名称或公众号样本。
- **端到端交付**：用户同时要求「先做风格概述，再做公众号风格写作 skill」。

如果缺少公众号名称，用素材标题、账号名、文档标题推断；推断不稳时只问一个问题：「这个公众号/账号希望用什么名字命名？」不要为了细节反复打断。

## 输入处理

支持这些输入：

- 飞书文档、飞书 wiki、飞书文件夹链接。
- 本地 Markdown、Word、PDF、文本文件或一个素材文件夹。
- 公众号文章链接、公众号历史文章导出、用户粘贴的文章合集。
- 已有「内容风格概述」文档。

处理飞书文档时使用 `lark-doc`：

1. 读取 `/Users/fanhan/.agents/skills/lark-doc/SKILL.md`。
2. 读取 `/Users/fanhan/.agents/skills/lark-doc/references/lark-doc-fetch.md`。
3. 创建飞书文档前读取 `/Users/fanhan/.agents/skills/lark-doc/references/lark-doc-create.md` 和 `/Users/fanhan/.agents/skills/lark-doc/references/style/lark-doc-create-workflow.md`。
4. 所有 `docs +fetch` / `docs +create` 都带 `--api-version v2`。

不要一上来全量读取超大文档。先 `outline` 看结构，再按类型和标题抽样精读。通常抽 8-15 篇即可：覆盖高频主题、代表性体裁、爆款/重要文章、早期和近期内容。若素材不足 5 篇，明确说明样本偏少，结论置信度较低。

## 阶段一：提取内容风格概述

### 分析顺序

按这个顺序工作：

1. **素材盘点**：列出来源、数量、时间跨度、内容类型、明显缺口。
2. **内容分群**：按主题和体裁分组，不要只按标题分类。
3. **作者画像**：判断作者站在什么位置说话，和读者是什么关系。
4. **创作路径**：还原不同体裁从选题到成文的决策链。
5. **思维内核**：提炼世界观、价值判断、问题意识、决策模式。
6. **表达特征**：拆语言质感、句式、节奏、修辞、标题、开头、结尾。
7. **可迁移规则**：把观察转成未来写作时能执行的规则。
8. **原文例证**：每个关键判断配短例证或定位说明。

重点寻找「可复用的生成规则」，而不是堆形容词。比如「平实」不够，要说明平实是如何实现的：短句、具体场景、少抽象判断、先讲亲历问题再给方法。

### 风格概述文档结构

创建飞书文档时使用 `references/style-overview-template.md` 的结构。根据素材调整标题，但保留这些核心板块：

- 风格概述与作者画像
- 内容类型与创作路径
- 思维内核
- 表达特征
- 创作习惯
- 可迁移写作规则
- 反模式与禁区
- 原文例证
- 样本覆盖与置信度

文档要能直接交付给用户，不要把它写成内部分析笔记。用结论先行的写法，每节先给判断，再给证据。

### 原文引用规则

可以引用短句证明判断，但不要大段复制原文。每个判断优先用「短引用 + 解释」或「文章标题/段落定位 + 解释」。如果用户要求完整摘录，提醒可能涉及版权或隐私，只摘必要片段。

## 阶段二：生成「xx 公众号风格写作」skill

当用户要求把风格概述做成 skill 时，使用 `skill-creator` 的原则，但不要照搬概述文档全文进 `SKILL.md`。做法是：

1. 读取风格概述文档，提炼成可执行写作流程。
2. 新建 skill 目录：`/Users/fanhan/.agents/skills/<账号名-公众号风格写作>`。
3. `SKILL.md` 的 `name` 使用「xx 公众号风格写作」。
4. `description` 要明确触发场景：用户要求按该公众号风格写、改、润色、诊断、仿写公众号文章时触发。
5. 把完整风格概述保存到新 skill 的 `references/source-style-overview.md`，供需要时读取。
6. 在 `SKILL.md` 中只放高频使用所需的风格摘要、工作流、写作模式、自检清单。
7. 如用户提供了公众号样本，把代表性原文片段和标题清单保存到 `references/source-samples.md`。

生成的写作 skill 至少支持四种任务：

- **诊断**：判断一篇稿子和目标公众号风格的差距。
- **润色**：在不改变事实和观点的前提下改写成目标风格。
- **从素材创作**：根据主题、素材、观点或访谈记录写一篇新公众号文章。
- **标题/开头/结尾优化**：单独优化文章关键部件。

使用 `references/generated-writing-skill-template.md` 起草新 skill，再按账号风格替换占位符。

## 公众号写作 skill 的质量标准

生成的新 skill 必须保留这些边界：

- 不编造经历、数据、客户案例、作者身份和公众号历史。
- 不把「风格复刻」做成表面口癖模仿；优先复刻选题逻辑、结构节奏、读者关系和论证方式。
- 不鼓励洗稿。若用户只给竞品文章并要求改成自己文章，先转为「提炼结构和写作方法，再用用户自己的素材重写」。
- 用户给出的事实、案例、观点优先级高于风格模板。
- 如果关键信息不足，最多问一个最影响成稿的问题；能先产出草稿就先产出。

## 交付格式

端到端任务完成后，给用户这些结果：

- 飞书「内容风格概述」文档链接。
- 新 Agent skill 的本地目录路径。
- 如已打包，给 `.skill` 文件路径。
- 简短说明这个 skill 之后适合处理哪些任务。

不要只在聊天里贴完整文档内容；用户要的是可复用资产落地。

## 自检清单

交付前检查：

- 是否真的读取了用户提供的素材，而不是凭空写通用风格词。
- 风格概述是否包含作者画像、创作路径、思维内核、表达特征、创作习惯、例证和置信度。
- 飞书文档是否已经创建并返回链接。
- 生成的公众号写作 skill 是否可独立触发、可独立使用。
- 新 skill 是否包含 `references/source-style-overview.md`。
- 是否避免了洗稿、编造事实和过度口癖化。
