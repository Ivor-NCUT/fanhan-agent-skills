# 泛函个人网站内容更新

让泛函只提供栏目选择和真实资料，其余信息整理、页面编辑、校验与按意图发布由本 Skill 完成。

## 入口

用户尚未说明栏目时，只展示下面的菜单并等待选择：

1. 候选人代表
2. 泛函的朋友们
3. 内容与课程
4. 精选活动
5. 有意思的社区或俱乐部
6. 精选影视艺术
7. 精选书籍

用户已经明确栏目时不要重复询问。确定栏目后，只读取 [对应栏目模板](references/intake-templates.md)，只展示该栏目的模板。说明用户可以按字段填写，也可以直接发送自然语言、链接和图片。

## 范围边界

- 仅可修改 `data-panel="candidates"`、`partners`、`works`、`events`、`communities`、`arts`、`books` 中被选中的栏目，以及它直接使用的图片、弹窗、栏目摘要和标签筛选。
- 禁止修改公司、岗位、`jobs-data.js`、岗位接口、岗位筛选、岗位分页及公司与岗位的同步逻辑。遇到此类请求时说明“公司和岗位由百纯维护”，不要代做。
- 不顺手调整首页、业务流程、全局视觉或其他栏目。一次请求可处理多个栏目，但每个栏目分别套用自己的模板。

## 收集资料

1. 先识别新增、修改或下线；未说明且资料指向新对象时按新增处理。
2. 将用户的自然语言整理进模板，不要求用户重新抄成表格。
3. 一次性追问所有缺失的必填项；可选项缺失就留空，不阻塞。
4. 不编造人物经历、推荐理由、数据、时间、链接或合作关系。可以压缩用户原文以适配卡片，但不得改变事实。
5. 修改或下线前用标题或姓名定位唯一卡片；有重名或目标不唯一时再问一句。
6. 图片只使用用户提供、仓库已有或明确允许公开使用的素材。二维码、微信号等联系信息只有在用户明确要求放到公开网站时才发布。

## 更新网站

目标仓库是 `Ivor-NCUT/fanhan-personal-website`。优先使用当前已打开且远端匹配的工作树；否则在当前设备上定位该仓库。开始前读取适用的 `AGENTS.md`，检查 Git 状态并保留已有改动。

- 复用网站现有的 `resource-card`、`partner-card`、标签、链接和弹窗组件，不为单条内容创造新视觉系统。
- 新条目默认放在所选栏目的最前面；用户指定顺序时服从指定顺序。
- 标题尽量控制在 28 个中文字符内，卡片简介尽量控制在 90 个中文字符内，标签保留 2–4 个。超长内容只做忠实压缩。
- 外链使用有效的 `https:` 或明确需要的 `mailto:`；新窗口链接添加 `target="_blank" rel="noreferrer"`。
- 图片放入 `assets/`，使用稳定、可读、不冲突的文件名，并提供准确的 `alt` 文本。
- 新增首条内容时移除该栏目的空状态；删除最后一条内容时恢复空状态。
- 更新所选栏目的真实数量、标签筛选与无障碍标签。不要手工改动其他栏目的统计。

用户说“更新、添加、修改到网站、上线、发布或同步”并随后提供资料，视为已授权完成对应内容的端到端更新。用户说“草稿、预览、先看看”时只生成本地预览，不推送或部署。删除、替换现有条目必须有明确的删除或替换意图。

## 验收与交付

1. 运行 `git diff --check` 和仓库已有的相关测试。
2. 在浏览器打开所选栏目，检查桌面与窄屏布局、图片、链接、标签筛选和空状态；不得让公司与岗位内容发生变化。
3. 若请求包含上线意图，按仓库既有流程提交、同步 GitHub、部署并回读线上页面；控制面超时后先回读状态，禁止盲目重复。
4. 最终只报告更新了哪个栏目、条目名称、是否已上线、验证结果和仍缺少的可选资料。
