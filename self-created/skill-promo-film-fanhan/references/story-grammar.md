# Skill 宣传片故事语法

## 核心命题

宣传片要证明“这个 Skill 如何改变一次真实任务”，而不是复述 README。先写出一句核心变化：

`原来的麻烦 → 用户给出一句指令 → Agent 做出关键判断与连续行动 → 形成可复用产物 → 产物在下一步被调用 → 得到具体结果`

如果某个场景不能推进这条因果链，就删除。

## 从 Skill 中选择内容

从事实清单里优先选择：

1. 用户最容易感知的入口指令。
2. Agent 与普通聊天工具不同的判断。
3. 两到四个能通过画面证明的执行动作。
4. 一个会被保存、继续使用或交付给人的产物。
5. 一个可信且具体的结果。

不要把所有功能都放进同一条片子。一次只保留一条主任务，其他能力留给下一条宣传片或真实演示视频。

## 镜头组织

镜头数和时长由内容及音乐决定，通常按下列功能选择，而不是机械全部使用：

| 故事功能 | 画面方式 | 动效目的 |
|---|---|---|
| 麻烦与入口 | 输入框、用户消息 | 让观众立即知道任务 |
| Agent 判断 | AI 流式回答 | 说明它为什么不是普通自动化 |
| 执行开始 | 安装卡、任务日志、文件创建 | 建立行动感 |
| 信息沉淀 | 文件逐行增加 | 证明结果可保存、可复用 |
| 批量处理 | 圆环网页、卡片流、左右工作区 | 压缩大量读取过程 |
| 关键变换 | 前后对比、字段替换、结构重排 | 让能力肉眼可见 |
| 人类控制 | 确认按钮、Review 状态 | 表达安全边界 |
| 外部结果 | 通知、联系人、已交付文件 | 给故事一个具体回报 |
| 收束 | 文件 Packshot、短句 | 固化核心价值 |

## 文案规则

- 中文屏幕文字要短、自然、像真实软件界面，不写广告腔旁白。
- 开场使用真实或高度可信的用户指令。
- AI 的第一句优先给判断，不先自我介绍。
- 执行中多用状态、文件名和结果，少解释概念。
- 最终结果若是剧情化演示，明确作为示意，不暗示保证发生。

## 音乐映射

- 开场弱拍：输入、光标或问题出现。
- 第一个明显重音：Agent 判断、窗口接管或关键卡片展开。
- 能量上升：执行步骤、文件写入、来源读取。
- 段落边界：任务阶段发生变化。
- 最强 accent：关键结果、确认或通知到达。
- 尾段回落：最终 Packshot 与品牌短句。

音乐决定速度和强调位置，不决定产品事实与故事逻辑。
