# 咨询记录整理@泛函

> 描述：将求职咨询的录音稿自动转化为结构化的 QA 文档，提炼问题和回答，按主题归类，保留关键细节，输出自然流畅的段落式记录。

接收用户提供的对话录音稿（通过 @引用 或直接粘贴）。快速浏览全文，理解对话的整体脉络和主要议题。

识别对话双方的角色：

- 仔细观察对话中的发言者标识（通常格式为「发言者名称(时间戳): 内容」）

- 分析对话内容，判断谁是来访者（提出问题、寻求帮助的一方），谁是咨询师（提供建议、解答疑惑的一方）

- 来访者通常会描述自己的困境、表达困惑、寻求建议

- 咨询师通常会提问、给出分析、提供解决方案和建议

- 记录下来访者和咨询师的名称，后续将用于标注问答

识别来访者的所有问题，包括：

- 直接提问（如"你现在做什么？"）

- 隐性关切（如"我现在很纠结"背后的求助）

- 追问和澄清（如"为什么会这样？"）

提取咨询师对每个问题的完整回答。如果一个问题引发了多轮对话，将相关内容整合在一起。

注意：有些问答可能是来访者自己提出问题并自己回答（自我陈述），这种情况下问题和答案都标注为来访者。

分析问答的内容属性，按主题归类。常见主题包括：

- 职业现状和方向

- 具体行业/岗位分析

- 个人状态和困惑

- 求职策略和建议

- 生活状态与压力

- 心理状态与成长

- 其他相关议题

同一主题下可能包含多个相关问答。

保留关键细节：

- 人名（如 Vincent、艾瑞斯、舒菲）

- 机构名（如 Monolith、Practice、真格）

- 数字信息（薪资、时间、数量等）

- 具体案例和故事

去除口语化的冗余表达（如"嗯

使用 write 工具创建新文档。

文档标题：原录音稿标题 + " QA 整理"

文档结构：

- 一级标题（#）：主题分类

- 二级标题（##）：具体问题，格式为「发言者名称：问题内容」

  - 如果是来访者的问题/陈述，用「来访者名称：问题」

  - 如果是咨询师的回答/建议，用「咨询师名称：问题」

- 正文：回答内容，用自然流畅的段落叙述

格式要求（严格遵守）：

- 严格禁止使用 bullet point（项目符号、数字列表）

- 所有内容用段落形式呈现

- 问题用加粗的二级标题标注，格式：## 发言者名称：问题内容

- 回答用自然流畅的段落叙述

- 段落之间用空行分隔

- 每个问答都要清楚标注是谁在问、谁在答
