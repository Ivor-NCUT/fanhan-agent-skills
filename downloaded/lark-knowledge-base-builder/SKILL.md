# 飞书知识库搭建

本 skill 的目标是把知识库建成“分层路标”，让人可以按月度或主题巡检，让 AI Agent 可以先读目录和摘要，再决定是否下钻正文，避免每次把整个知识库读完。

## 先读这些能力边界

执行飞书写操作前，先读取：

1. `../lark-wiki/SKILL.md`：创建知识空间、节点、移动节点、读取节点层级。
2. `../lark-doc/SKILL.md`：创建和编辑飞书 Docx 文档，尤其是 `docs +create --api-version v2` 与 `docs +update --api-version v2`。

如果只是为用户设计结构草案，还没有实际创建飞书内容，可以不读取底层 skill 的详细参考文件。

## 核心原则

把每个知识库设计成三层导航：

1. **总目录文档**：知识库第一篇文档。它告诉人和 Agent：这个知识库有哪些子目录、每个子目录解决什么问题、查询时应该先去哪里。
2. **子目录指引文档**：每个子目录的第一篇文档。它简述本目录下有哪些文档、分别记录什么、遇到哪些问题时应该读哪篇。
3. **正文首块摘要**：每篇正文文档的第一个内容块。用几句话概括这篇文档包含哪些知识、适合回答哪些问题、什么时候不必继续读正文。

这样 Agent 的读取路径是：先读总目录，定位子目录；再读子目录指引，定位具体文档；最后读正文首块摘要，判断是否读取全文。

## 输入澄清

开始前快速确认这些信息；如果用户已经给出，就不要重复追问：

- 目标：新建知识库、重构已有知识库，还是只输出结构方案。
- 范围：知识库主题、服务对象、资料来源、预计子目录数量。
- 落点：飞书知识空间 URL / space_id / 父节点 URL；如果用户给了多个飞书链接，先确认最终要创建到哪个知识库或节点。
- 输出：只要目录设计、要创建飞书文档、还是要把已有文档移动并补摘要。

当落点不明确时，先停下来确认。飞书知识库里“知识空间、节点、文档”不是同一层对象，建错位置会让后续查询路径失效。

## 搭建流程

### 1. 盘点材料

先把用户提供的资料拆成“问题域”，而不是按文件来源机械分类。每个问题域应该能回答一类真实查询，例如“客户案例怎么找”“月度复盘在哪里”“某类 SOP 是否存在”。

输出一个轻量盘点表：

| 子目录 | 服务的问题 | 典型读者/Agent 查询 | 主要文档 |
| --- | --- | --- | --- |

### 2. 设计目录树

目录层级保持浅而稳：

- 第一层：总目录文档。
- 第二层：3-9 个子目录。少于 3 个通常不用拆知识库；多于 9 个先合并成更高层问题域。
- 第三层：正文文档。正文文档可以很多，但每篇都必须能被子目录指引解释清楚。

避免把“日期、作者、文件类型”作为第一分类，除非用户的查询习惯本身就是按这些维度查。

### 3. 写总目录文档

总目录文档放在知识库顶部，标题建议为：

`00 知识库总目录`

正文使用这个结构：

```markdown
# 00 知识库总目录

本知识库用于：[一句话说明知识库范围和边界]

## Agent 查询路线

1. 先根据问题判断应进入哪个子目录。
2. 进入对应子目录后，先读该目录的 `00 目录指引`。
3. 只在正文首块摘要显示匹配时读取全文。

## 子目录索引

| 子目录 | 主要内容 | 适合查询的问题 | 不适合查询的问题 |
| --- | --- | --- | --- |
| [子目录名] | [内容范围] | [问题类型] | [边界] |

## 维护规则

- 新增子目录时，同步更新本总目录。
- 新增正文文档时，同步更新所属子目录的 `00 目录指引`。
- 正文文档第一块必须是摘要，不要直接进入长正文。
```

### 4. 写子目录指引

每个子目录下创建第一篇文档：

`00 目录指引`

正文使用这个结构：

```markdown
# 00 目录指引

本目录用于：[说明该目录的问题域]

## 先读规则

遇到以下问题，优先查本目录：
- [问题 1]
- [问题 2]

遇到以下问题，不要在本目录继续消耗 token：
- [边界 1]
- [边界 2]

## 文档索引

| 文档 | 记录内容 | 适合回答的问题 | 阅读建议 |
| --- | --- | --- | --- |
| [文档名] | [内容摘要] | [问题类型] | [先读首块摘要/可直接全文读/只查表格等] |
```

### 5. 给正文文档补首块摘要

正文文档第一个块必须是摘要块。推荐格式：

```markdown
> 本文摘要：本文记录 [主题/对象] 的 [核心知识类型]，主要用于回答 [问题 A、问题 B]。如果你要找 [不属于本文的问题]，应返回上级目录改查 [更合适的目录/文档]。
```

摘要要短，但要有边界。不要只写“本文介绍 XXX”，那对 Agent 决策帮助不够。

### 6. 实际创建或重构

如果用户要求直接落到飞书：

1. 用 `lark-wiki` 解析或创建目标知识空间、父节点和目录节点。
2. 用 `lark-doc` 创建总目录、子目录指引和正文文档，创建/编辑文档时携带 `--api-version v2`。
3. 创建后再用 `lark-wiki` 把文档节点移动到正确目录。
4. 最后列出实际落点：知识空间、父节点、总目录文档、每个子目录指引和正文文档链接。

如果是重构已有知识库：

1. 先列出当前节点树，不要直接移动。
2. 输出“现状 -> 建议结构 -> 需要移动/新增/补摘要的文档”。
3. 获得用户确认后再执行写操作。

## 交付格式

无论是否实际创建，最后都要给用户一个清晰交付：

- `知识库总目录`：标题或链接。
- `子目录结构`：每个子目录一句话说明。
- `Agent 查询路径`：用 3-5 步说明 AI 应该如何省 token 查询。
- `已创建/待创建清单`：区分已落地和需要用户补资料的部分。

## 质量检查

交付前检查：

- 总目录是否能让 Agent 不读正文就知道有哪些子目录。
- 每个子目录是否有 `00 目录指引`。
- 每篇正文的第一块是否能判断“读不读全文”。
- 边界是否写清楚，避免 Agent 在错误目录继续查。
- 实际飞书落点是否与用户指定的知识库、父节点或 URL 一致。
